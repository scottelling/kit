# Operate Purple Rain Studio

Own the whole outcome. Keep the user in plain language, make safe decisions autonomously, and return finished visual work rather than a tutorial.

## Studio sequence

1. Discover the project authority. Read repository instructions, locked conventions, existing brand material, prior decisions, deployment records, and live surfaces. Separate facts from gaps. Do not invent a design system where one already exists.
2. Turn the request into a working project receipt: audience, job, project family, success condition, voice, constraints, required surfaces, and release target.
3. Choose or create a complete connected template with `$compose-complete-template`. A template is a system of real journeys and states, not a collection of disconnected sections.
4. Establish or tune the creative system with `$direct-creative-labs`. Carry brand, type, color, text treatment, and motion as one direction.
5. Use `$build-brand-system` when identity work is needed and `$design-ui-system` for foundations, components, patterns, responsive rules, and interaction states.
6. Build the full working product. Preserve existing user work, use the project’s real stack, and keep public controls and messages understandable without implementation knowledge.
7. Run `$prove-release`. The quality mark is automatic only after the actual checks pass. Repair failures before deployment.
8. Deploy through the established project path, inspect the live result, and record the release proof.

## Direction rules

- Preserve the current brand and design authority unless the user explicitly requests a new direction.
- When direction is genuinely open, create three structurally different options and select the strongest using the brief and constraints.
- Keep the current object, its state, and the next action obvious.
- Use real content structure. Never invent customer names, testimonials, metrics, awards, partnerships, inventory, or claims.
- No glass, translucent decoration, glow, decorative gradients, ambient blobs, floating-card hover lifts, or looping resting motion.
- Do not volunteer task-duration or completion-time estimates unless the user asks for one in the current message.

## Completion contract

Do not call the project finished until the important journeys work with keyboard and touch, responsive layouts hold at narrow and wide sizes, difficult states exist, reduced motion works, the production build passes, the live deployment matches the intended release, and the evidence is recorded in plain language.
